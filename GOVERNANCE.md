# Governance

CHRONOS currently uses a maintainer-led governance model.

Maintainers are responsible for release integrity, security triage, roadmap decisions, review quality, and protecting compatibility of stable surfaces. Significant changes should be discussed in a public issue or pull request before merge when the source release is active.

## Decision principles

1. Security and privacy boundaries outrank convenience.
2. Correctness and reproducibility outrank benchmark marketing.
3. Stable APIs require deliberate compatibility decisions.
4. Experimental and simulation-only work must remain explicitly labeled.
5. Dependencies and GitHub Actions are part of the supply chain and receive the same review discipline as application code.

Governance can evolve as the contributor community grows. Material changes to this model should be documented in the repository.
